# Схема базы данных

## Таблица `"user"`

Хранит пользователей системы, их пароли (SHA‑1) и данные для блокировки.

| Поле | Тип | Описание                                                        |
|------|-----|-----------------------------------------------------------------|
| `id` | SERIAL | PRIMARY KEY                                                     |
| `login` | VARCHAR(25) | Логин пользователя, уникальный                                  |
| `password` | VARCHAR(40) | Хэш пароля (SHA‑1)                                              |
| `email` | VARCHAR(30) | Email пользователя                                              |
| `login_attempts` | INTEGER | Количество неудачных попыток входа (по умолчанию 0)             |
| `locked_until` | TIMESTAMP | Время до которого аккаунт заблокирован (NULL = не заблокирован) |

**Ограничения:**
- `CHECK (CHAR_LENGTH(login) > 8 AND CHAR_LENGTH(password) > 8)` — логин и пароль длиннее 8 символов
- `UNIQUE (login)` — логин уникален

---

## Таблица `worker`

Содержит объекты `Worker`, привязанные к пользователю.

| Поле | Тип | Описание |
|------|-----|----------|
| `worker_id` | VARCHAR(25) | PRIMARY KEY, уникальный идентификатор работника |
| `name` | VARCHAR(100) | Имя работника |
| `user_id` | INTEGER | Внешний ключ на `"user"(id)`, при удалении пользователя удаляются его объекты |

**Ограничения:**
- `NOT NULL` для `worker_id` и `name`
- `UNIQUE (worker_id)`

---

## Таблица `password_reset_tokens`

Хранит одноразовые 6‑значные коды для восстановления пароля.

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | SERIAL | PRIMARY KEY |
| `user_id` | INTEGER | Внешний ключ на `"user"(id)` |
| `code` | VARCHAR(6) | 6‑значный код восстановления |
| `expires_at` | TIMESTAMP | Время жизни кода (например, 1 минута) |
| `attempts` | INTEGER | Количество неудачных попыток ввода кода (по умолчанию 0) |
| `used` | BOOLEAN | Был ли код уже использован (по умолчанию FALSE) |

---

## Таблица `email_verification_tokens`

Хранит временные данные регистрации и 6‑значные коды для подтверждения email.

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | SERIAL | PRIMARY KEY |
| `email` | VARCHAR(30) | Email, на который отправлен код |
| `login` | VARCHAR(25) | Логин нового пользователя |
| `password_hash` | VARCHAR(40) | Хэш пароля (SHA‑1) |
| `code` | VARCHAR(6) | 6‑значный код подтверждения |
| `expires_at` | TIMESTAMP | Время жизни кода (например, 30 минут) |
| `attempts` | INTEGER | Количество неудачных попыток ввода кода (по умолч. 0) |
| `used` | BOOLEAN | Был ли код уже использован (по умолч. FALSE) |

**Индексы:**

| Индекс | Поля | Назначение |
|--------|------|------------|
| `idx_email_verification_code` | `code` | Быстрый поиск по коду (при подтверждении) |
| `idx_email_verification_email` | `email` | Поиск незавершённых регистраций по email |

---

## Логика подтверждения email при регистрации

1. Пользователь вводит `login`, `password`, `email` (команда `register`).
2. Сервер:
   - Проверяет, нет ли пользователя с таким `login` или `email` в таблице `users`.
   - Генерирует 6‑значный код.
   - Сохраняет запись в `email_verification_tokens` (логин, хэш пароля, email, код, `expires_at = NOW() + INTERVAL '30 minutes'`).
   - Отправляет код на email.
   - Возвращает ответ: *«Код подтверждения отправлен на email»*.
3. Пользователь вводит `confirm_email <code>`.
4. Сервер:
   - Ищет запись с таким `code`, где `used = FALSE` и `expires_at > NOW()`.
   - Если находит:
      - Создаёт пользователя в таблице `users` (берёт `login`, `password_hash`, `email` из записи).
      - Помечает запись как `used = TRUE`.
      - Возвращает успех: «Email подтверждён, регистрация завершена».
   - Если код неверен, истёк или уже использован:
      - Увеличивает `attempts` (до 3 попыток).
      - При `attempts >= 3` код становится недействительным (удаляется запись или `used = TRUE`).
      - Возвращает ошибку: «Неверный или просроченный код».

---

## Отличие от `password_reset_tokens`

| Характеристика | `email_verification_tokens` | `password_reset_tokens` |
|----------------|-----------------------------|--------------------------|
| Назначение | Подтверждение email при регистрации | Восстановление пароля |
| Содержит | Логин, email, хэш пароля | Только `user_id` (ссылка на пользователя) |
| Время жизни | 30 минут | 1 минута / 1 час |
| После успеха | Создаётся запись в `users` | Обновляется пароль в `users` |

| Индекс | Таблица | Поля | Назначение |
|--------|---------|------|------------|
| `idx_worker_worker_id` | `worker` | `worker_id` | Быстрый поиск по ID работника |

## Логика блокировки

1. При неудачной попытке входа `login_attempts` увеличивается на 1.
2. При `login_attempts >= 3` аккаунт блокируется: `locked_until = NOW() + INTERVAL '1 hour'`.
3. При успешном входе или восстановлении пароля:
    - `login_attempts = 0`
    - `locked_until = NULL`
4. Если при попытке входа обнаруживается, что `locked_until < NOW()` — блокировка автоматически снимается, счётчик обнуляется.

---

## Логика восстановления пароля

1. Пользователь запрашивает восстановление → генерируется 6‑значный код.
2. Код сохраняется в `password_reset_tokens` с `expires_at = NOW() + INTERVAL '60 seconds'`.
3. Код отправляется на email.
4. Пользователь вводит код → проверяется:
    - Код существует
    - `used = FALSE`
    - `expires_at > NOW()`
5. При успешной проверке:
    - Пароль обновляется
    - Код помечается `used = TRUE`
    - `login_attempts = 0`, `locked_until = NULL`
6. При неверном вводе `attempts` увеличивается на 1. При `attempts >= 3` код аннулируется (удаляется или помечается `used = TRUE`).
