# Схема базы данных

## Таблица `"user"`

Хранит пользователей системы, их пароли (SHA‑1) и данные для блокировки.

| Поле | Тип | Описание                                                        |
|------|-----|-----------------------------------------------------------------|
| `id` | SERIAL | PRIMARY KEY                                                     |
| `login` | VARCHAR(25) | Логин пользователя, уникальный                                  |
| `password` | VARCHAR(40) | Хэш пароля (SHA‑1)                                              |
| `email` | VARCHAR(30) | Email пользователя                                              |

**Ограничения:**
- `CHECK (CHAR_LENGTH(login) > 8 AND CHAR_LENGTH(password) > 8)` — логин и пароль длиннее 8 символов
- `UNIQUE (login)` — логин уникален

## Таблица `worker`

Содержит объекты `Worker`, привязанные к пользователю.

| Поле          | Тип          | Описание                                                                      |
|---------------|--------------|-------------------------------------------------------------------------------|
| `id`   | SERIAL       | PRIMARY KEY, уникальный идентификатор записи                                  |
| `worker_id`   | VARCHAR(25)  | уникальный идентификатор работника                                            |
| `name`        | VARCHAR(100) | Имя работника                                                                 |
| `user_id`     | INTEGER      | Внешний ключ на `"user"(id)`, при удалении пользователя удаляются его объекты |
| `create_date` | DATE         | Время добавления сотрудника в базу, default now()                             |

**Ограничения:**
- `NOT NULL` для `worker_id` и `name`
- `UNIQUE (worker_id)`

## Индексы

| Индекс | Таблица | Поля | Назначение |
|--------|---------|------|------------|
| `idx_worker_worker_id` | `worker` | `worker_id` | Быстрый поиск по ID работника |
| `idx_worker_name` | `worker` | `name` | Быстрый поиск по имени |
| `idx_user_login` | `"user"` | `login` | Ускорение поиска по логину |
| `idx_user_password` | `"user"` | `password` | Ускорение аутентификации |
| `idx_user_login_password` | `"user"` | `login, password` | Составной индекс для входа |

## Логика восстановления пароля

1. Пользователь запрашивает восстановление → генерируется 6‑значный код.
2. Код отправляется на email.
3. Пользователь вводит код → проверяется:
    - если код введен правильный -- предлагается ввести новый пароль, после чего пароль заменяется и пользователь входит в аккаунт.
    - если код введен неверный, то у пользователя есть три попытки ввести верно, если за три попытки не удалось ввести верный код, то необходимо запросить новый код.

---
## Логика регистрации
1. Пользователь вводит электронную почту → генерируется 6‑значный код.
2. Код отправляется на email для подтверждения электронной почты.
3. Пользователь вводит код → проверяется:
   - если код введен правильный -- предлагается ввести логин и пароль.
   - если код введен неверный, то у пользователя есть три попытки ввести верно, если за три попытки не удалось ввести верный код, то необходимо запросить новый код, либо вернуться в меню входа.
